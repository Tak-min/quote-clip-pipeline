# BRIEF: 名言切り抜きショートの著作権リスク × リターン（council ループ）

## ゴール
`~/quote-clip-pipeline`（YouTube等の動画を切り抜き→字幕→縦型ショート→TikTok/Meta系へ自動投稿）を
**実際にどう運用すれば、著作権リスクに見合うリターンが得られるか**を決め切る。
最終成果物は `research/copyright/DECISION.md`：ユーザーがそのまま運用ルールとして使える1枚。

## 必ず読むもの
- `~/quote-clip-pipeline/README.md`（パイプラインの仕様）
- `~/quote-clip-pipeline/research/market_test_loops.md`（市場テストの設計 v6）
- `~/meigen-app/docs/persona.md`（アプリのターゲット。§0 の確定事項は変えない）

## ユーザーの確定事項（覆さない。ただしリスクとしては評価する）
- 素材の権利判定をパイプラインに組み込まない（最も簡単な形で作る方針）
- 偉人＋アニメの名言。日本語・英語の2アカウント。末尾1〜2秒にアプリ名だけ。リンクなし
- 投稿先は TikTok と Meta系（Instagram / Facebookリール / Threads）
- 投稿文の「出典URL」と BGM クレジット（CC BY 4.0）を残すか消すかは未決 → これもこのループで決める

## 回す論点（各周で最低1つを深掘り）
1. リスクの中身: 日本法（引用32条・権利制限・非親告罪化の範囲）、米国フェアユース、各SNSの著作権ポリシーとストライク/アカウント停止の実運用（TikTok, Instagram, Facebook, Threads）、Content ID / Rights Manager 相当の自動検出、アニメ（制作委員会）と偉人の講演・インタビュー映像（放送局・TED等）での違い
2. リターン: 切り抜き形式で得られる到達・フォロー・アプリ名の想起と、代替形式（AI音声＋静止画/素材映像、テキストのみのカード動画、本人の声なし字幕のみ 等）で失うもの
3. 実際の運用方法: どの素材は使う／使わない、1アカウントあたりの許容損失（BAN前提の捨てアカ運用か）、削除申し立てが来た時の手順、アプリ本体（App Store審査・IP通報）へ波及させない分離
4. SNSマーケのどの場面を自動運用に回し、どこを手動・別形式にするか（例: 市場テスト期は切り抜き、アプリ公開後はアプリ画面の録画やオリジナル形式へ移行 など）
5. 競合 Shift の「著作権ガン無視」レビューから学べること（ブランド毀損）

## 方法（必須）
- 1周 = 主張 → 実際に調べる（一次情報優先: 法令・各SNSの公式ポリシー・判例・公式ヘルプ）→ council で批判 → 判定 → 設計修正。
- council: `council-executor` / `council-expansionist` / `council-first-principles` / `council-outsider` / `council-red-team` の5席を並列で起動し、`council-peer-review` で匿名相互レビュー、最後に自分で統合。各席には上の確定事項と、その周の主張・根拠ファイルのパスを自己完結の形で渡す。
- 毎周の記録を `research/copyright/loops.md` に追記（周番号、主張、根拠URL、各席の要点、判定、変更点）。
- Claim（事実）と Bet（賭け＋撤退条件）を分けて書く。法的な断定はしない（弁護士ではない）。「この運用ならリスクはこの程度、最悪ケースはこれ」という形で書く。

## 停止条件（/goal の完了条件）
- loops.md に**実際に調べて回した周が5周以上**あり、うち council 実行が2回以上
- DECISION.md に次の5項目がすべてある:
  ① 結論（切り抜きを使うか・どの範囲で）② 素材ごとの使う/使わない表（偉人講演、TED、テレビ放送、アニメ本編、映画）③ アカウント運用ルール（ストライク時の手順含む）④ 自動運用に回す場面／回さない場面 ⑤ 投稿文の出典URL・BGMクレジットの扱い
- 最終周で「前の周から結論が変わらなかった」こと

## 禁止
- 実投稿・アカウント作成・外部への書き込み・課金はしない
- パイプラインのコードは変更しない（提案は DECISION.md に書く）
- ユーザーに質問しない。迷ったら記録した上で保守的な方を選ぶ
