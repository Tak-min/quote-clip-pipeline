## 第1周（council 第1回）— 論点1: 法的リスクの中身（日本法・米国法・素材別）

### 主張（周の初め）
切り抜きは日本法の「引用」(32条)にも米国フェアユースにも当たらない可能性が高い。ただし刑事リスク（非親告罪）は限定的で、現実の主リスクは民事の削除要請とSNSのアカウント処分。素材によって差が大きく、TED とアニメ本編は避けるべき。

### council 第1回（5席並列 → 匿名相互レビュー）
ブリーフ: `council/round1_brief.md` / 各席の回答（匿名A〜E）: `council/round1_seats.md`
席の対応: A=Executor, B=First Principles, C=Outsider, D=Expansionist, E=Red Team

- **Executor(A)**: 4SNS×2言語の自動投稿で1件の申立てが全アカウントに波及。主リスクは「削除」より「アカウント処分で市場テストが無効になる」こと。sources.csv の3本はすべて組織が権利者で低リスク素材がない。段階投入と処分記録を。
- **First Principles(B)**: 「刑事は限定的」は断定できない（宮城県警の例は加工済みアニメでも有罪）。末尾のアプリ名カードが「商業・同目的」を自ら作る。**切り抜き映像の需要と名言そのものの需要を混同している**——PD演説・CC講演・自前朗読でもほぼ同じ精度で測れる。
- **Outsider(C)**: 実際の門番は法律ではなく、プラットフォームの検知と自動処分。字幕翻訳は翻案(27条)・同一性保持(20条)、実名＋姿の宣伝利用はパブリシティの論点。IP苦情はApp Store開発者アカウントや TikTok/Meta の開発者アプリ（API権限）へ波及し得る。
- **Expansionist(D)**: 日本発の投稿に米国法を並べるなら準拠法の整理が要る。需要検証に原典映像は必須ではない（没後70年超の偉人、CC素材、自作の朗読＋フリー背景）。rights_lane の手書きラベルでレーン別に比べる。
- **Red Team(E)**: 主張は「アニメ本編は避ける」なのに sources.csv にハイキュー名場面集（第三者の転載＝権利が二重に不明）があり、ペルソナ主力仮説B2（アニメ）と矛盾。FBページ・IG・Threads は同じMeta基盤で一蓮托生。通知が来たら即削除・対抗通知は出さない。
- **相互レビュー**: 全席が「修正して採用」で**合意が揃いすぎ（suspicious consensus）**。全席の見落とし: ①申立ては数週間遅れて来る（24〜72時間の静けさ≠安全）②LLM意訳字幕と発言者テロップによる**名言の誤帰属**（権利とは別の信用毀損）。出典URLを残す効果は誰も検証していない。

### 判定
**修正して採用。** 修正後の主張: 切り抜きは「引用」にもフェアユースにも当たらない可能性が高く、刑事リスクが限定的とも断定できない。ただし現実に起きやすいのは、検知による削除・アカウント処分と、それによる市場テストの無効化・アプリ事業への波及。素材ごとに差が大きい。

### 設計の変更点（v1）
1. 主リスクの定義を「法廷」→「①アカウント処分 ②アプリ事業（開発者ID・審査）への波及 ③市場テストの汚染」に変更
2. 素材を手書きの区分（tier）で分ける。判定コードは入れない（確定事項どおり）
3. TED は使わない（公式に禁止）。アニメ本編は「優先度を下げる」→ 次周で SNS 側の実運用を見て最終判断
4. 申立ての遅延を前提に、観察期間と停止しきい値を先に決める（次周以降）
5. 名言の誤帰属チェックを論点に追加
6. 未検証のまま持ち越し: 出典URLを残す効果 / 123条2項の「原作のまま」に短い切り抜きが入るか

## 第2周 — 論点1（SNSの処分の実運用・自動検出）＋論点3（API経由の波及）

### 主張（周の初め）
各SNSの処分は「ストライク制で段階的」なので、少量・段階投入なら1アカウントの損失で済み、捨てアカ運用（BAN前提）で吸収できる。投稿は API で自動化してよい。

### 自己批判（council なし周。5つの視点で自分で点検）
- 実行: 「TikTok を API で自動投稿」は**ガイドライン上ほぼ通らない**（2-3: 自社アカウント向けアップロードツール・他プラットフォームからのコピーは明示的に不可）。監査に出すと開発者アプリ自体に記録が残る。
- 第一原理: 「段階的だから1アカウントで済む」は誤り。Meta は1件でもアカウント全体を見直す（2-5）、FB・IG・Threads は1つの基盤（2-8）、開発者アプリまで止まり得る（2-7）。損失単位は「1動画」ではなく「1言語のMeta一式＋API」。
- 外部視点: 処分が無くても、unoriginal 判定（2-4, 2-6）で**おすすめに乗らない＝リターンが出ない**。リスクの前に、リターンが構造的に削られる。
- 拡張: TikTok は「アプリ内で手動アップロード」なら API ガイドラインの対象外。生成は自動、投稿だけ手動（1本約2分。market_test_loops Loop6 の見積もり）に戻せば成立する。
- レッドチーム: 捨てアカ運用は TikTok ポリシー（2-1: BANされた人の新規作成拒否の留保）と衝突し、BAN回避とみなされる恐れ。**「捨てアカ前提」は採らない**。

### 判定
**棄却して作り直し。** 主張の「捨てアカ前提」「API 自動投稿でよい」はどちらも成り立たない。

### 設計の変更点（v2）
1. 損失単位を「1言語あたり Meta一式（IG+FB+Threads）＋Metaの開発者アプリ」と定義。アプリ本体の広告・ログイン等に使う Meta/TikTok 開発者アプリとは**別の開発者アカウント**にする（アプリ事業への波及を切る）
2. TikTok は **API を使わずアプリ内で手動投稿**（監査申請もしない）。Meta 系は Graph API の自動投稿を続けてよいが、無許諾素材は流さない（2-7）
3. 捨てアカ・BAN後の作り直しはしない。1言語のアカウントが重い処分を受けたら、その言語の切り抜き運用は終了
4. 「意義ある編集」の要素を明確にする（引きの一言・訳字幕・発言者テロップは既にある）。ただしこれは配信の改善で、権利の問題は解決しない

### 主張（周の初め）
切り抜き形式（本人の映像・声）は代替形式より到達が圧倒的に大きく、アプリ名の想起も強い。リスクを取る価値がある。

### 自己批判（5視点）
- 実行: 切り抜きが代替形式より伸びるという**公開データは見つからなかった**（主張の根拠なし）。言えるのは「unoriginal 判定（2-4, 2-6）で切り抜きは伸びが削られる」ことだけ。
- 第一原理: アプリが売るのは「名言＋発言者名」であって映像ではない。動画で需要を確かめたいのも名言の需要。**アニメの「体温」は映像より、作品名・キャラ名・その言葉で呼び起こせる**（ペルソナ 3-7 の「誰が言ったかが一目で」）。
- 外部視点: Shift の★1（3-1）は「映画の切り抜きで集客」を**アプリのストアページに書かれた**。評価件数が少ない初期ほど1件の★1が目立つ。切り抜きのリスクは SNS ではなくストアで顕在化する。
- 拡張: 「名言テキストカード」動画 = アプリのシェア画像と同じ見た目にすれば、SNSで見た人がアプリで同じものを見る（ブランドの一貫性）。将来アプリ画面の録画にそのまま移れる。
- レッドチーム: テキストカードは再生が落ちる可能性がある（Bet）。また末尾1.5秒のアプリ名は形式に関係なく見られにくい（3-3）ので、「切り抜きの方が想起が強い」も根拠がない。

### 判定
**棄却。** 「切り抜きの方が圧倒的に伸びる・想起も強い」は根拠がない。確かな差は「切り抜きは権利・配信抑制・ストア評価の3方向で損をする」こと。ただしテキストカードで再生が落ちる可能性は残るので、Bet として小さく比べる。

### 設計の変更点（v3）
1. **アニメは映像を使わない**: 名言テキスト＋作品名（＋キャラ名）＋自前の背景・CC BY BGM のカード動画。キャラ画像・本編映像・声は使わない
2. **偉人は「再利用の許可が明示された素材」か「権利者が政府等で著作権がない素材」だけ切り抜き**、それ以外はテキストカード
3. Bet B-1: テキストカードでも反応は取れる。撤退条件は §5 で DECISION に記載（数字の基準は置かず「明らかに伸びない」を人が判断）
4. 名言の誤帰属対策: 発言者が確かめられない言葉は使わない（手で選ぶ sources 側で落とす）

- 実行: 公式許可の切り抜きは YouTube 前提（4-1, 4-2）。このパイプラインの投稿先（TikTok・Meta）は**対象外**。許可条件を作品ごとに読むのは「権利判定」そのもので、確定事項（権利判定を組み込まない＝最も簡単な形）と相性が悪い → 例外扱いは作らない方が簡単で安全。
- 第一原理: 対抗通知は「自分に権利がある・誤りだ」と宣誓するもの（4-3）。無許諾の切り抜きでは宣誓の前提がなく、出せば実名・住所を相手に渡し、米国の裁判管轄に同意することになる。**対抗通知は出さない**が正しい。
- 外部視点: アプリ本体は「名言テキスト＋発言者名」を載せる。短い言葉は保護されにくい（3-4）が、アニメのキャラ画像・ロゴを使えば 5.2.1 に直撃（4-4）。SNS側でキャラ画像を使わないことは、アプリ本体と同じ線を守ることになる。
- 拡張: 「権利者が明示的に TikTok/Instagram での利用を許可した素材」（例: 本人が自分の講演を自由に使ってよいと書いている、CC BY で商用・改変可）は、手で選ぶなら判定コードなしで使える。
- レッドチーム: 削除が来た動画を消すだけでは、Meta はアカウント全体を見直す（2-5）。**1件目で同じ素材系統を止める**ことが重要。

### 判定
**棄却（緩めない）。** 公式許可アニメの例外は YouTube 前提で投稿先に合わず、作品ごとの条件読みは確定事項に反する。対抗通知は出さない。

### 設計の変更点（v4）
1. 素材表を確定（DECISION ② に記載）: アニメ本編・映画・テレビ放送・TED は映像を使わない。偉人講演は「商用・改変・TikTok/Meta での利用が明示的に許された素材」か「米国政府著作物（PD）」だけ切り抜き、それ以外はテキストカード
2. 削除申し立て時の手順: その動画を全SNSから自分で削除 → 同じ元動画・同じ発言者／作品の未投稿分を止める → 対抗通知・異議は出さない → 記録
3. アプリ本体: キャラ画像・ロゴ・本編スクショを使わない（SNSと同じ線）

## 第6周（最終周）— 論点1・3の残り: v6 で新しく入れた線（存命人物を外す／アニメ台詞のカード／作品名の表示）は妥当か

### 主張（周の初め）
DECISION v6 の結論①（基本はテキストカード、切り抜きは許可素材だけの任意枠）は、第5周で足した「存命人物は使わない」「アニメは短い台詞＋キャラ名＋作品名のカード」を含めても変わらない。

### 調べたこと（Claim）

### 自己批判（5視点。council は第1・5周で実施済み）
- 実行: v6 の運用は現行コードを変えずに「`publish` しない」ことで守れる。カード生成の実装（1〜2日）が済むまでは、テキストカードを手作業で作っても同じ線を守れる。結論に影響なし。
- 第一原理: 存命人物の実名をアプリ宣伝動画に付ける形は、6-1 の類型③「広告として使う」に近づく。侵害かどうかは「専ら」の判断次第で断定できないが、**保守側に倒す v6 の判断を補強**する。故人の言葉を外す理由は見つからなかった。
- 外部視点: 短い台詞は保護されにくい（6-2）が、保護される例もある（6-3）。v6 の「1枚は短い一言」は必要条件で、リスクはゼロではない → v6 のリスク表（「小さいが残る」）と B-4（アニメカードで申し立てが来たら作品を外す）で既に扱っている。結論に影響なし。
- 拡張: 作品名・キャラ名を出典として書くことは商標の「自分の商品名として使う」用法ではない（6-4）。アプリ名と作品名を並べて「公式コラボ」に見せる表現（「〇〇公式」「〇〇×アプリ名」等）だけは避ける → ②の注意に1行足す（結論は不変）。
- レッドチーム: 「切り抜きをほぼ使わないなら、パイプラインの主機能が無駄になる」という反論は、第5周の相互レビューでも結論①を覆す指摘にならなかった。字幕・翻訳・BGM・アプリ名カード・投稿の部品はカード生成で再利用される。新しい反証は見つからなかった。

### 判定
**採用（前の周から結論は変わらない）。** 第5周の結論①〜⑤をそのまま維持。変更は②への注意書き2行（短い言葉でも保護される場合がある／公式コラボに見せない）のみで、使う・使わないの線は動かない。

### 変更点（v6 → v6.1、文言のみ）
1. ②「テキストカードでも守ること」に: 短い言葉でも著作物と認められた例がある（6-3）ので、印象的な長めの決め台詞ほど慎重に
2. ②に: 作品名・キャラ名は出典として書くだけ。「公式」「コラボ」に見える表現はしない（6-4）
