# DECISION: 名言ショートの著作権運用ルール（v6.1）

対象: `~/quote-clip-pipeline` の運用（日本語・英語の2アカウント、TikTok＋Meta系）。根拠と経緯は `loops.md`（第1〜6周、council 2回）。
法的な断定ではない（弁護士の確認は受けていない）。「この運用ならリスクはこの程度、最悪ケースはこれ」という形で書く。

---

## ① 結論

**基本は「名言テキストカード動画」。他人の映像の切り抜きは、再利用の許可が明示された素材が実際に見つかったときだけ使う任意の枠にする。**

- テキストカード = 名言の言葉＋文字の出典（発言者・年・場面／キャラ名・作品名）＋自前の背景＋CC BY の BGM＋末尾のアプリ名。他人の映像・音声・キャラ画像は使わない。
- 切り抜きを使ってよいのは、故人の偉人の講演のうち「商用・改変・SNSでの利用」が**権利者本人により**明示的に許されたもの、または米国政府の著作物（著作権なし）だけ。
- アニメ・映画・テレビ・TED・許可のない講演は、**映像も音声も使わない**（テキストカードにする）。
- 確定事項はそのまま: 権利判定はパイプラインに入れない（人が `sources.csv` に書く段階で選ぶ）／偉人＋アニメ／2アカウント／末尾にアプリ名だけ／リンクなし／TikTok＋Meta。

**なぜ**（番号は loops.md の Claim）
1. 無許諾の切り抜きは日本の「引用」(32条)にも米国フェアユースにも当たらない可能性が高い。アプリ宣伝の動画は商業目的で、元と同じ「鼓舞」の目的（Warhol 判決で不利: 1-5）。刑事も「限定的」とは言えない（2023年、字幕付きアニメ動画の投稿者が逮捕・有罪: 1-4）。
2. 現実の損失は SNS 1本の削除ではなく、**1言語の Meta 一式（IG・FB・Threads）と開発者アプリの停止**（2-5, 2-7）、そして**アプリのストアページの★1**（競合 Shift:「著作権ガン無視 — 映画などを無断で切り抜いて集客」: 3-1）。
3. 切り抜きの方が伸びるという根拠は見つからなかった。一方、切り抜きは TikTok・Meta の「オリジナルでないコンテンツ」としておすすめから外されやすい（2-4, 2-6）。
4. アプリが売るのは「名言＋誰が言ったか」で、映像ではない。テキストカードはアプリのシェア画像と同じ見た目にでき、SNSで見たものとアプリで見るものが一致する。

**リスクの見積もり**
| 運用 | 起きやすいこと | 最悪ケース |
|---|---|---|
| この DECISION どおり | BGM の誤クレーム（第三者が曲を登録: 5-3）。許可素材の読み違いで削除1件。同じ見た目のカードの量産で「オリジナルでない」扱い・おすすめ外し。テキストカードの再生が伸びない | アニメ台詞カードへの申し立てで1言語の SNS アカウントが機能制限。アプリへの波及は**小さいが残る**（アプリ名が出ているため） |
| 無許諾の切り抜きを続けた場合（参考） | 削除・ミュート・おすすめ外し。アニメ権利者（CODA 等）の申し立て | 1言語の Meta 一式＋開発者アプリの停止、ストアに★1、民事請求（ファスト映画は1再生200円で算定・5億円: 1-3）、刑事告訴 |

## ② 素材ごとの使う／使わない表

| 素材 | 映像・音声の切り抜き | 名言テキストカード | 理由（loops.md の番号） |
|---|---|---|---|
| **偉人の講演・インタビュー**（大学の式典、企業イベント、本人チャンネル等） | **原則使わない。** 例外: 故人で、権利者本人が「商用・改変・SNSでの再利用可」と明示（CC BY / CC BY-SA 等、NC・ND なし）／米国政府の職務著作（PD） | **使う**（故人のみ。文字出典つき） | 講演の言葉（本人側）と映像（主催者側）の二重の権利。ジョブズの Stanford 講演は再利用条件が見つからない（1-7）。米国政府著作物は著作権なし（3-6） |
| **TED / TEDx** | **使わない** | 使う（故人の言葉のみ。TEDのロゴ・映像なし） | TED 公式が「切り抜き」「宣伝利用」を明示的に禁止（1-6） |
| **テレビ放送**（番組、CM、スポーツ中継、ニュース） | **使わない** | 故人の言葉なら使う | 放送局・制作会社・事務所の権利 |
| **アニメ本編**（名場面集・公式PV・配信の録画すべて） | **使わない**（公式に切り抜き許可がある作品でも、許可は YouTube 前提で TikTok/Meta は対象外: 4-1） | **使う**（短い台詞1つ＋キャラ名＋作品名。キャラ画像・ロゴ・本編スクショ・声は使わない） | 製作委員会・CODA の監視、字幕付きアニメ投稿で逮捕例（1-4） |
| **映画** | **使わない** | 使う（同上） | Shift の★1の直接の原因（3-1）。ファスト映画の5億円判決（1-3） |
| **存命の人物**（スポーツ選手・経営者・タレント等） | 使わない | **既定で使わない** | 実名＋末尾のアプリ名で「本人がアプリを推薦している」ように見える（第5周 T席）。保守側を選ぶ |
| 政治家の公開演説（参考） | 言葉は40条で利用可。**映像は撮影者（局）の権利なので使わない** | 故人なら使う | 40条は言葉の話で、映像の権利は別（3-5） |

**切り抜きの許可を確かめるとき（人が `sources.csv` に書く前に）**
- YouTube 等の「CC BY」表示は投稿者の自己申告。**投稿者が権利者本人（本人・主催団体の公式チャンネル）か**を確かめる。再アップロードは使わない。
- 映像の中に第三者の音楽・映像が入っていないか見る。
- 許可の文面（ライセンス表示・利用規約）のスクリーンショットとURLを `research/copyright/licenses/` に保存する。

**テキストカードでも守ること**
- 発言者が確かめられない言葉（出典不明のまま広まった「名言」）は使わない。誤った人物名で広めるのは権利とは別の信用問題。
- 1枚は短い一言。長い台詞・歌詞・本の段落は丸写ししない（短い言葉は保護されにくいが、長い文章は保護され得る: 3-4, 6-2）。短い標語でも著作物と認められた例がある（6-3）ので、印象的な長めの決め台詞ほど慎重に。
- 作品名・キャラ名は出典として書くだけ。「〇〇公式」「〇〇×アプリ名」など、公式コラボに見える表現はしない（6-4）。
- 本人の声を AI で再現しない。
- カードの見た目（背景・配色・BGM）は毎回少し変える。同じテンプレートの機械的な量産は「オリジナルでない」扱いの対象になり得る。

**今の `sources.csv` の3行への当てはめ**
| 行 | 判定 |
|---|---|
| スティーブ・ジョブズ（Stanford 講演） | 切り抜きは使わない → テキストカード（「— スティーブ・ジョブズ, 2005年 スタンフォード大学卒業式」） |
| 松岡修造 | **使わない**（存命）。行を消す |
| ハイキュー!!（第三者がアップした名場面集） | 切り抜きは使わない → テキストカード（台詞＋キャラ名＋『ハイキュー!!』）。この動画のURLは出典にもどこにも書かない（無断転載物） |

**アプリ本体も同じ線**: 名言テキスト＋発言者名／キャラ名・作品名まで。キャラ画像・ロゴ・本編スクショは使わない（App Store 審査 5.2.1: 4-4）。アプリ内の名言の扱いは、SNS とは別にアプリ側の課題として確認する。

## ③ アカウント運用ルール

**構成**
- 言語ごとに: TikTok 1 ＋ Meta 一式（Instagram プロアカウント・Facebook ページ・Threads）。偉人とアニメは同じアカウントで混ぜてよいが、アニメの本数は全体の半分までにする（アニメ側の処分が偉人側の積み上げを巻き込むのを抑える）。
- **アプリ本体とは分ける**: SNS 投稿用の Meta 開発者アプリ・Meta ビジネスは、アプリの広告・ログイン・SDK に使うものとは**別に作る**（Meta Platform Terms 7(e): 2-7）。同じ本人なので完全な隔離にはならないが、1つの停止で両方が止まる形は避ける。Apple の開発者アカウントは分けられないので、②の素材ルールで守る。
- **捨てアカ・BAN後の作り直しはしない**（TikTok は BAN された人の新規作成を拒否できる: 2-1）。

**投稿の量**
- 立ち上げ1週目は各言語1日1本（`--limit 1`）。問題がなければ1日2〜3本まで。
- TikTok はアプリ内で手動投稿（④参照。1日最大6本×約2分＝約12分）。

**削除・ストライク・ミュートが来たときの手順**
1. **通知の原因を見る**: BGM（Kevin MacLeod の曲）への申し立てか、映像・言葉への申し立てか。
2. **BGM が原因のとき**（第三者による誤登録が多い: 5-3）: その動画の曲を別の曲に差し替えて出し直すか、CC BY 4.0 のクレジットを根拠にアプリ内で異議を出す。その曲は以後使わない。下の停止ルールには数えない。
3. **映像・言葉が原因のとき**: **当日中に**その動画を全SNSから削除する（IG・Threads・FB は API で削除できる: 5-4, 5-5。TikTok はアプリで手動）。同じ元動画・同じ発言者／作品の未投稿分を外し、`sources.csv` のその行を消す。
4. **異議・対抗通知は原則出さない**（米国 DMCA の対抗通知は偽証罪つきの宣誓・実名住所・米国裁判管轄への同意が必要: 4-3）。例外は②で許可文面を保存してある切り抜きだけで、その場合は保存した根拠を示して異議・説明を出してよい。権利者から直接連絡が来たら、謝罪して削除済みと返す。
5. `output/posted.json` の該当行に、日付・SNS・通知の種類（削除／ミュート／警告／おすすめ対象外）・原因を手で書く。
6. 切り抜き動画で1件来たら → **その言語の切り抜きを止め、テキストカードだけにする。**
7. テキストカードで来たら → その作品／発言者を外す。同じアカウントで2件目 → その言語の投稿を2週間止めて素材を見直す。
8. アカウントの機能制限・停止の通知が来たら → その言語の SNS 運用を止める。作り直さない。アプリ名は変えない。
9. 申し立ては数週間遅れて来ることがある。「数日何もない＝安全」と読まない。TikTok のストライクが90日で消えても（2-2）、リセットとして使わない。

## ④ 自動運用に回す場面／回さない場面

| 場面 | 自動 | 手動 |
|---|---|---|
| 素材選び（`sources.csv` に書く） | | **手動**。②の表で選ぶ。カード行は言葉と文字出典を手で書く。権利判定のコードは入れない |
| 名言区間の選定・字幕・翻訳・縦型化・BGM・アプリ名カード（切り抜き行） | **自動**（今のパイプライン） | `--select-only` で選ばれた言葉と発言者が正しいかだけ確認 |
| 名言テキストカード動画の生成 | **自動**（要実装。下記） | 最初の3〜5本は出来上がりを目で見る |
| Meta 系（IG・FB・Threads）への投稿 | **自動**（Graph API）。ただし最初の3〜5本は `--dry-run` で確認してから1本ずつ手動で流し、問題がなければ自動に | |
| TikTok への投稿 | | **手動**（アプリ内でアップロード）。Content Posting API は「自社アカウント向けアップロードツール」「他プラットフォームからのコピー」を不可としており、監査が通らない見込み（2-3）。監査申請もしない |
| 削除通知・コメント対応 | | **手動**（③の手順） |
| 週1回、各SNSのアカウント状態画面を見る | | **手動**（5分） |

**時期による移行**
1. **アプリ公開前（市場テスト期）**: テキストカード中心。許可素材の切り抜きは見つかったときだけ少量。
2. **アプリの画面ができた時点（TestFlight 等）**: テキストカードを**アプリのシェア画像・ウィジェットと同じデザイン**に揃え、「ロック画面のウィジェットに名言が出る様子」など**アプリ画面の録画**を少しずつ混ぜる。アプリ自身の画面なので他人の権利の問題がない。
3. **アプリ公開後**: アプリ画面の録画とテキストカードが主。切り抜きは②の許可素材だけで、広げない。

**パイプラインへの提案（コードはまだ変えていない。見積もり 1〜2日）**
- `sources.csv` に `mode` 列（`clip` / `card`）、カード用の `quote` 列と `cite` 列（文字出典）、切り抜き用の `license` / `author` 列を足す。**`mode` が空なら `card` として扱う**（改修漏れで無断転載物のURLが出る事故を防ぐ）。
- `card` 行は動画を取得せず、言葉・発言者・作品名からカード動画を作る（既存の字幕描画・BGM・アプリ名カード・ラウドネス処理を再利用。日英の改行・禁則、背景素材の用意、フォントの商用利用条件の確認を含む）。
- `quote_clips/run.py` の `build_meta()` は今すべての投稿に `出典: {url}` を入れる → ⑤のとおり分岐させる。**改修が終わるまで、今のパイプラインのまま `publish` しない。**
- 削除用に `publish` へ「指定した動画を IG・FB・Threads から消す」コマンドを足す（5-4, 5-5）。

## ⑤ 投稿文の出典URL・BGMクレジット

| 項目 | 決定 | 理由 |
|---|---|---|
| **BGM クレジット**（Kevin MacLeod, CC BY 4.0） | **残す**（今の自動挿入のまま、使った1曲だけ） | CC BY 4.0 の利用条件（作者名・ライセンス表示・リンク: 5-1）。消すとこちらがライセンス違反になる。消したい場合は incompetech の有料 Standard License を買う（5-2）。誤クレームへの異議の根拠にもなる |
| **出典 — テキストカード** | **URL は入れない。文字の出典を入れる**: 偉人は「— 発言者名, 年, 場面」（例: 「— スティーブ・ジョブズ, 2005年 スタンフォード大学卒業式」）、アニメは「— キャラ名『作品名』」 | 映像を使っていないので URL は不要。無断転載の動画（例: ハイキュー名場面集）へのリンクは侵害物への誘導になる。文字の出典は誤帰属を防ぎ、信用になる |
| **出典 — 許可素材の切り抜き** | **入れる**: 元動画 URL＋作者名＋ライセンス名（例: 「CC BY 4.0」） | CC BY 系なら表示は条件そのもの（5-1） |

## Bet（賭け）と撤退条件

| Bet | 中身 | 撤退条件（人が判断） |
|---|---|---|
| B-1 | テキストカードでも、保存・シェア・「アプリどこ？」コメントなどの反応が取れる | 新しいアカウントは最初の数十本は伸びないのが普通なので、20本程度で「名言の需要なし」とは結論しない。反応がほぼ無いときは**映像を足す方向には戻らず**、先に形式を変える（①自分の声で読む版 ②アプリ画面の録画）。それでも無ければ、需要の仮説を見直す |
| B-2 | 許可素材の切り抜きは削除されない | 映像・言葉が原因の削除・ミュートが1件でも来たら、その言語の切り抜きを止める（③-6） |
| B-3 | 分けた開発者アカウントと②の素材ルールで、アプリ本体への波及は防げる | Meta / Apple からアプリ側に知的財産の連絡が1件でも来たら、SNS 投稿を全停止して原因を調べる |
| B-4 | アニメ台詞の短いテキストカードは申し立てを受けにくい | アニメのカードで申し立てが1件来たら、その作品を外す。2作品目で来たら、アニメのカードを止めて偉人（故人）だけにする |
